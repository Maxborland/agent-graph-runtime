# Agent Graph Runtime v0.7 delivery specification

Status: implemented; final verification and independent review pending. This document narrows the approved v0.7
roadmap into observable behavior for the current delivery branch. It does not
claim that the behavior is released until every acceptance criterion passes on
the final revision.

## Goal

A human can run repository-writing graphs locally with recoverable versioned
state, append-only attempt evidence, drift-bound single-use approvals,
at-most-once external-action dispatch, and explicit reversible Git integration
without mutating an unrelated user checkout.

## Non-goals

- Dynamic graph patches, resource-aware scheduling, hosted UI, remote workers,
  SQLite, and distributed leases (v0.8+).
- npm publication, automatic merge, deployment, or destructive Git history
  operations.
- Provider-owned authentication or API-key storage.
- Automatic reconciliation of uncertain external effects.

## Public interface

- Existing v0.6 graph files and commands remain accepted.
- `agr approve NODE TARGET [GRAPH]` issues one immutable receipt bound to the
  current graph, repository, dependencies, action parameters, and plan revision.
- `agr retry NODE [GRAPH] --reconciliation FILE` is required when retrying an
  uncertain external action; ordinary safe retries keep the existing form.
- `agr integrate RUN_ID [GRAPH] [--target BRANCH] [--dry-run]` previews or
  integrates an immutable completed run result.
- `agr rollback RUN_ID [GRAPH] [--dry-run]` previews or creates a revert commit
  for a recorded integration.
- Read commands transparently inspect legacy or v0.7 persisted runs.

## Acceptance criteria

- **AC1 — coherent versioned storage:** every new state, event, evidence, report,
  plan revision, authority record, and run result carries an explicit schema
  version. A single authoritative generation pointer selects a coherent state
  and event pair.
- **AC2 — deterministic legacy migration:** an unversioned v0.1-v0.6 run migrates
  under the run lock, preserves a hashed backup, derives the same base plan
  revision on repeated inspection, and never combines half-migrated files.
- **AC3 — fail-closed recovery:** malformed, mixed-cursor, hash-mismatched, or
  ambiguous persisted artifacts are rejected before mutation with an actionable
  diagnosis. A process interruption at any generation publication seam selects
  the prior or next complete generation. Abrupt power or storage loss is not
  claimed durable without filesystem flush guarantees and fails closed.
- **AC4 — optimistic mutation:** a stale expected state revision cannot commit a
  second mutation.
- **AC5 — append-only attempts:** each node start creates a globally unique
  attempt ID with a monotonic per-node ordinal. Retry creates a new generation
  without resetting or deleting prior attempts.
- **AC6 — immutable evidence:** evidence paths include attempt IDs, carry hashes
  and producer identity, and remain byte-identical and addressable after three
  retries and descendant invalidation.
- **AC7 — current versus history:** status, inspect, why, logs, events, and report
  identify the current attempt while retaining superseded attempt history.
- **AC8 — bound authority:** an approval receipt becomes unusable after target,
  action parameter, plan revision, repository, dependency evidence, policy, or
  expiry drift. Receipt reuse is denied.
- **AC9 — human root authority:** a deterministic policy may narrow an explicit
  human mandate but cannot expand it. Sensitive or unknown external effects
  require an exact human receipt by default.
- **AC10 — at-most-once external dispatch:** every external action reserves and
  consumes one receipt durably before coordinator-local dispatch. Any non-success
  or uncertain post-reservation outcome enters reconciliation and is never
  automatically dispatched again.
- **AC11 — explicit reconciliation:** retrying an uncertain external action
  requires hashed reconciliation evidence and a newly issued receipt; resume or
  repeated `agr run` cannot bypass either requirement.
- **AC12 — isolated writing run:** a writing run executes from an exact base
  commit in a repository-local run worktree and branch. The primary checkout,
  including dirty and untracked files, remains unchanged.
- **AC13 — immutable result and checkpoints:** accepted waves create checkpoint
  commits containing run/evidence metadata. Completion creates one immutable
  `RunResult`; later operations append records rather than mutate it.
- **AC14 — explicit integration:** dry-run reports fast-forward, cherry-pick, or
  conflict without mutation. Real integration verifies lineage, evidence, clean
  final checks, and authority, writes a durable intent, then appends an
  `IntegrationRecord`. Restart reconciles a provably applied expected tree and
  blocks ambiguous replay.
- **AC15 — reversible rollback:** rollback previews and then creates a revert
  commit plus immutable `RollbackRecord`; it never resets, cleans, force-pushes,
  or claims to reverse external effects.
- **AC16 — committed run chaining:** a new writing run starts only from an exact
  explicit commit, including a selected prior result commit, never another run's
  mutable worktree.
- **AC17 — compatibility:** legacy read-only runs remain inspectable; existing
  graph validation and executor adapters remain provider-agnostic.
- **AC18 — package acceptance:** TypeScript build, full Node test suite, package
  dry-run, Markdown links, and staged-diff checks pass on the final revision.
- **AC19 — safe runtime identity:** unsafe or path-like run and node IDs are
  rejected before any runtime artifact path is resolved. Compatible logical IDs
  with spaces retain their run directory while Git names use a collision-resistant
  stable suffix.

## Failure behavior and edge cases

- Missing Git identity, non-repository roots, unborn branches, submodules,
  symlinks, binary files, Windows paths, dirty target branches, merge conflicts,
  stale worktrees, duplicate commands, and already-integrated or already-reverted
  results fail with explicit next actions.
- An external-action crash between reservation, consumption, dispatch, and
  outcome recording always prefers possible duplication prevention over
  automatic progress.
- Runtime artifacts stay outside product commits. Failed and cancelled worktrees
  remain recoverable until the human explicitly prunes them.
- Hash or repository drift invalidates authority; checks never repair drift
  silently.

## Assumptions

- The current draft PR and branch are the implementation surface.
- Git is available for writing runs; read-only graphs may continue without an
  isolated worktree.
- The human supplies and authenticates Codex, Claude Code, or Claudex locally.
- Retention remains manual in v0.7.

## Traceable test plan

- AC1-AC4 → generation migration, current-pointer, corruption, crash-seam, and
  stale-revision tests in `test/store-recovery.test.ts`.
- AC5-AC7 → lifecycle, invalidation, runner evidence, report, observation, and
  log tests using repeated attempts.
- AC8-AC9 → authority unit/integration tests covering every bound field, expiry,
  receipt reuse, and mandate escalation.
- AC10-AC11 → runner and CLI fixtures counting actual effects across failure,
  interruption, restart, resume, and explicit reconciled retry.
- AC12-AC13 → Git transaction fixtures with clean and dirty primary checkouts,
  checkpoint metadata, and immutable result hashes.
- AC14-AC16 → CLI integration/rollback fixtures for preview, fast-forward,
  divergent, conflict, duplicate, revert, and committed chaining behavior.
- AC17 → existing v0.6 fixture suite plus legacy artifact fixtures.
- AC18 → `pnpm test`, `pnpm pack --dry-run`, local Markdown link validation, and
  `git diff --check`.
